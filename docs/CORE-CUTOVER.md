# Changing a Core tier

`core-models.json` in this repo is the **public copy** of the Core lineup that installed
Atlarix apps read (hourly). The proxy never reads it: the proxy serves Core from its own
bundled config, which is the source.

## How a tier changes

1. Change the tier in the proxy's bundled config, in a proxy PR (dev → main). The new
   lineup is live once that deploy finishes.
2. Regenerate the public copy from it in the proxy repo (`node scripts/public-core-models.mjs`;
   a test fails if the two drift apart).
3. Copy the generated file over `core-models.json` here, in a PR. The sync job then
   regenerates the tables in this repo, including the lineup below.

An edit made only here changes what the apps display but not what the proxy serves.
Routing details (providers and the rest of the server-side config) live only in the proxy
and never come back into this file.

The **wire id** is the name the app and models.dev use for the model. The **API model id**
is what the provider is called with. The table is generated by
`scripts/gen-readme-models.mjs`; don't edit it by hand.

## Before you change a model id

- **The API model id must match models.dev's spelling exactly, including case.** It is the
  key for the price and context-window lookup. A wrong spelling loses the tier's price, so
  it bills at its worst-case reserve, and loses its context window.
- Run `node scripts/pick-core-model.mjs` to check that the id exists in models.dev, and
  `node scripts/pick-core-model.mjs --check` to audit the current lineup. It exits non-zero
  on a problem.
- A tier left out of `models` is read as empty everywhere, and clients fall forward to a
  configured tier. That is also the quickest way to take a broken tier out.

## After a change

- No "no price row" warnings in the proxy logs. That warning means the price lookup missed.
- Per-request charges sit well under their reserve.
- Wallet debits reconcile against the provider's own reported spend over about a day. This
  is the check that proves the money path.
